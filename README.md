Gosto de construir sistemas que resolvem problema de verdade — daqueles que rodam em produção, com gente dependendo deles no dia a dia, e não só em demo bonita.

Hoje passo boa parte do tempo pensando em **como colocar IA dentro de fluxos reais sem perder o controle**: com contexto certo, limites claros e rastreabilidade de ponta a ponta. A ideia é que a IA ajude a decidir, não que decida sozinha.

### 🔧 No que estou mexendo agora

Camadas de orquestração de IA com guardrails e trilha de auditoria. Plataformas para operações do dia a dia, como agendamento, apoio à decisão e automação. Serviços pesados em dados no modelo pay-as-you-go. Monitoramento e alertas em tempo real a partir de fontes externas. E, claro, ferramentas internas com LLMs para acelerar desenvolvimento e documentação.

### 🧭 Como eu trabalho

Começo pela especificação, não pelo código. Primeiro defino as regras do sistema, depois organizo os requisitos, desenho a solução e só então parto para a implementação — usando IA como acelerador, nunca como substituto do raciocínio.

No caminho, algumas coisas que levo a sério:

- **Simples > esperto.** Código "genial" costuma virar dívida.
- **Tudo que importa precisa ser rastreável.** Logs, traces e métricas desde o primeiro dia.
- **O modelo só vê o que precisa ver.** Menor exposição de dados possível.
- **Custo é requisito.** Dá para economizar infraestrutura sem abrir mão de confiabilidade.
- **Pensar no longo prazo.** Sistema bom é sistema que dá para manter e evoluir.

### 🛠️ Ferramentas do dia a dia

TypeScript em modo strict (e sem `any`, por favor), Node.js e Bun no backend, React e Tailwind no front, MongoDB, Docker e OpenTelemetry. Zod para contratos, APIs idempotentes nas operações críticas e arquitetura orientada a eventos quando ela realmente faz sentido. Ultimamente também tenho estudado orquestração de containers para alta disponibilidade.
